\section{Introduction} \label{sec:intro}
\textcite{axiomatch2026planetree} proved that any efficient order book must maintain a forest of trees. Their assumptions are extremely mild:
\begin{enumerate}
    \item The order book supports limit order placement and market order sweep.
    \item Market order sweep is $o(N)$, and the cost of sweep writes is minimized.
\end{enumerate}
The central property is staleness: If the sweep is $o(N)$, it cannot write every tick it crosses. The orders on the unwritten ticks are logically taken, but physically untouched. Such a tick is called stale. This is the operational definition of staleness in \textcite{axiomatch2026planetree}.

However, \textcite{axiomatch2026planetree} only proved a necessary condition. As such, they did not establish existence. Most importantly, their operational definition of staleness is hard to check in practice. We propose a semantically static definition of staleness and prove its equivalence to the operational one. We also propose an algorithm for resolving the staleness using only $N+1$ storage and prove that using only $N$ storage is impossible.
\paragraph{Related work}
The resolution of staleness is a long-standing topic in computer science (\Cref{tab:ancestors}). The technique is as follows.
\begin{itemize}
    \item Use a global clock to set the local clock when an object is initialized.
    \item Compare the local clock with a comparator at a future time to invalidate the object.
\end{itemize}

\paragraph{Our contribution}
We propose an algorithm that achieves resolution of staleness using $N+1$ storage. We prove the optimality in storage and the correctness of the algorithm. This is important because for Java and \texttt{make}, a wrong verdict raises an exception and warrants a rebuild. For order book, a wrong verdict erases a live order or revives a stale order. Either way, a user's funds are lost.
